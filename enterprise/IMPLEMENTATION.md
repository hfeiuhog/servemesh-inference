# 企业共享推理平台实施与演练

## 前置条件

授权的 GPU Kubernetes 集群，已有 production-stack 基线部署、监控、镜像仓库和模型下载授权。先用相同模型/固定采样参数建立吞吐、首 token 延迟、P95、错误率基线；本仓库不提供虚构性能数字。
`EndpointInfo.model_label` 是策略池名来源，应与实际模型工作负载标签一致。默认策略关闭；启用前配置两个合成租户和实际端点池，使用 HTTPS 网关和内部网络策略阻止绕过 Router。

## 发布顺序

1. CI 验证代码与 Helm，构建本分支 Router 镜像并固定 digest。
2. 在受控系统创建至少 32 字节的签名 Secret；只授权可信入口和 Router 访问。
3. 参考 values-shared-inference.yaml 设置 tenantRouting、现有 Secret、池名与阈值；配置自建 Router 镜像。
4. Helm 预览和预发布部署。入口验证用户后生成最长五分钟的上下文，重写全部 x-servemesh-* 头。
5. 先对合成租户放量，观察 servemesh_route_decisions_total，再按真实业务验收计划扩展。

| 演练 | 预期 |
|---|---|
| 无效签名/过期上下文 | 拒绝路由 |
| 请求指定不允许池的直接端点 | 不允许绕过过滤 |
| 所有允许端点拥塞/无指标 | 503，无跨池降级 |
| 会话重复请求、候选健康且同负载窗口 | 稳定选择 |
| 首选端点严重过载 | 选择允许池中较低负载候选 |
| 语义缓存或 external provider 同时启用 | 启动失败，提示不兼容 |

## 限制与回滚

阈值基于异步采样，不是原子资源预留；存在采样延迟，不保证严格并发/成本配额。亲和路由旨在增加缓存命中机会，没有测得的命中率提升数字。
回滚应先把租户流量切回既有受控入口，再回滚 Helm release 和镜像。不要在仍接收签名租户流量时直接切成无过滤策略。轮换密钥会使旧上下文失效，安排入口和 Router 协调轮换。
